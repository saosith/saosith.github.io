# saosith.github.io

My professional site and portfolio of analog/mixed-signal IC design work. Built
with [Astro](https://astro.build), deployed to GitHub Pages by GitHub Actions.

Each project is published as a datasheet rather than a gallery: a parameter table
with targets beside results, the test conditions those results were taken under,
a visible badge saying whether the numbers came from a hand model, a simulator or
silicon, and a download link to the dataset behind every plot.

## Before you publish: replace the example content

The site ships with worked examples so every component is visible and working.
**Most of it describes designs that are not yet real.** Work through this list:

- [ ] **Site details → Resume** — upload your CV in the CMS. The nav, the footer
      and the home-page button all read the path from `src/data/site.json`, so
      one upload updates every link. Until then they point at the placeholder
      `public/resume.pdf`.
- [ ] **Site details → Photo** — upload a headshot. The home page shows an
      explicit "add a photo" placeholder until you do.
- [ ] **About page → Timeline** (in the CMS, or `src/data/about.json`) — two
      entries are flagged as placeholders and render a visible "replace this
      entry" chip. Rewrite them with real dates, real organisations, and a link
      to a real artifact, then untick the flag. **Do not ship invented
      credentials.**
- [ ] **About page → Tools** — anything without a project link renders as
      "coursework". Keep that distinction honest.
- [ ] **Projects** — all three worked examples ship as `draft: true`, so
      **nothing is published yet**. Open one in the CMS, replace the numbers and
      the write-up, then untick Draft. Or add a new project from scratch; every
      field carries a description. Until something is published the home page
      shows a placeholder where the flagship chart goes, and the projects index
      says so.
- [ ] **Notes** — the two technical notes ARE published. They are example
      content too; set `draft: true` in their frontmatter (or untick in the CMS)
      if you would rather start clean.
- [ ] `public/data/*.json` — currently generated by `npm run data`, which builds
      **analytical model data, not simulation output**. Replace with real ngspice
      results (see below), then set `dataStatus: simulated` in the project's
      frontmatter so the badge changes.
- [ ] `public/og.png` — not present. Add a 1200×630 PNG and the social-card meta
      tag turns itself on automatically (`src/layouts/Base.astro` checks for the
      file). Without it, LinkedIn previews show title and description only.
- [ ] **Site details** (in the CMS, or `src/data/site.json`) — name, email, and
      profile links live there only.

## Editing without touching code

The repo is configured for [Pages CMS](https://pagescms.org) — a free, hosted
admin UI that reads `.pages.yml` and commits to this repository on your behalf.
You never see git; saving fires the deploy workflow and the public site updates
a minute or two later.

**Connect it once:**

1. Go to <https://app.pagescms.org> and sign in with GitHub.
2. Grant access to this repository.
3. It picks up `.pages.yml` automatically. No config in the app.

Only people with write access to the repo can log in, so the editor is
effectively private without any extra auth.

**What you get as forms**

| Section | What you can edit |
|---|---|
| Projects | Every frontmatter field as a proper form — spec table rows, headline numbers, tags, footnotes, links, the provenance badge, draft/featured toggles |
| Notes | Title, summary, date, tags, body |
| About page | Timeline entries and the tools list (`src/data/about.json`) |
| Site details | Name, tagline, email, profile links (`src/data/site.json`) |
| Media | Upload images and PDFs to `public/uploads/`, referenced as `/uploads/<name>` |

**What it deliberately does not do well.** Project bodies are MDX containing
component calls like `<BodeFigure … />`, and notes contain fenced SPICE and
shell blocks. Both body fields are configured as plain text rather than
rich-text, because a WYSIWYG editor would re-serialise that markup and could
mangle it. Editing prose through the CMS is fine; leave the `import` lines and
`<Figure />` tags alone, and write new project bodies in an editor.

New entries take their filename from the title, so a new project called
"Folded-cascode OTA" becomes `folded-cascode-ota.mdx` at
`/projects/folded-cascode-ota/`. New projects default to `draft: true` and stay
out of the build until you untick it.

`_TEMPLATE.mdx` appears in the projects list in the CMS. It is `draft: true`, so
it never publishes — ignore it, or copy it as a starting point.


## Deploying

Pushing to `main` triggers `.github/workflows/deploy.yml`, which builds and
publishes to GitHub Pages.

**One-time setup:** in the repository settings, under Pages, set *Source* to
**GitHub Actions**. This repo previously used the Jekyll "deploy from branch"
mode; the workflow will not publish until that is changed.

For a custom domain, add `public/CNAME` containing the domain and update `site`
in `astro.config.mjs`.

## Getting real simulation data onto the site

The charts read JSON from `public/data/`. `scripts/raw-to-json.mjs` converts
ngspice rawfiles into that format and derives DC gain, the unity-gain crossover
and phase margin from the curve itself — so the summary table under each plot
can never drift away from the trace above it.

```bash
# 1. write ASCII rawfiles (add `.option filetype=ascii` to the deck)
for c in TT FF SS FS SF; do
  ngspice -b -D corner=$c -r sim/ac_$c.raw sim/opamp_ac.spice
done

# 2. convert
node scripts/raw-to-json.mjs \
  --out public/data/opamp-ac.json \
  --node "v(out)" \
  --source simulated \
  --conditions "VDD = 1.8 V, T = 27 °C, CL = 2 pF" \
  TT=sim/ac_TT.raw FF=sim/ac_FF.raw SS=sim/ac_SS.raw \
  FS=sim/ac_FS.raw SF=sim/ac_SF.raw

# 3. flip `dataStatus: model` -> `simulated` in the project's frontmatter
```

Run `node scripts/raw-to-json.mjs --help` for the full options.

## Writing a project

Copy `src/content/projects/_TEMPLATE.mdx`. The filename becomes the URL. The
frontmatter drives the spec table, the sidebar, the index card and the filter
tags; the body is MDX, so figures are imported and placed inside the narrative:

```mdx
import BodeFigure from '../../components/BodeFigure.astro';

<BodeFigure figNo="Fig. 3" caption="What the reader should notice." />
```

Available figure components:

| Component | What it renders |
|---|---|
| `AnnotatedSchematic` | Clickable block diagram; each block explains its sizing rationale |
| `BodeFigure` | Gain/phase over log frequency, per-corner toggles, hover readout, corner summary table |
| `MonteCarloFigure` | Mismatch histogram against a spec window, with yield statistics |
| `BandgapFigure` | Linear line chart (V(ref) over temperature) with hover readout |
| `DesignExplorer` | Sliders driving the first-order op-amp model, with a live redrawn response |

Set `draft: true` to keep a page out of the build.

## Layout

```
src/
  components/     figures, header, footer, spec table, status chips
  content/
    projects/     one .mdx per project  (_TEMPLATE.mdx to copy)
    notes/        one .md per note
  layouts/        page shell, meta tags, theme handling
  data/           CMS-editable content (about.json, site.json)
  lib/
    charts.ts       hand-rolled SVG charts (no charting dependency)
    opamp-model.ts  the first-order model behind the explorer
    site.ts         types + structural values over data/site.json
    about.ts        types + grouping over data/about.json
  pages/          routes
  styles/         design tokens and component styles
.pages.yml        Pages CMS editing forms
scripts/
  gen-sample-data.mjs   generates the placeholder model datasets
  raw-to-json.mjs       ngspice rawfile -> chart JSON
public/data/      the datasets the charts fetch (and visitors can download)
```

## Notes on the design

- **Charts have no dependency.** They need log axes, engineering-notation ticks,
  phase-margin annotation and theme-aware colours; that was less work to write
  than to configure. The series palette is validated for colour-vision
  deficiency in both light and dark mode, and every chart ships a table
  alternative and a hover readout.
- **Provenance is structural, not editorial.** `dataStatus` in frontmatter drives
  a visible badge. It is deliberately hard to present a model as a measurement.
- **Conditions travel with the data.** They live in each dataset's `meta` block
  and render above the plot, so a bandwidth is never quoted without its load.
